# 消融实验：自动判白点到底解决了什么

> 本文件由 `scripts/report_ablate.py` 生成，`--check` 会因数字漂移而失败。
> 数据源 `tools/hdr_ablate.c`（全 C、无依赖），四个合成场景各跑 60 帧到稳态。

四档策略（每档都在同一套直方图/ITM 之上，只有「怎么定拐点」不同）：

- **fixed** — 固定拐点 0.55/1.0，不看画面（老式做法）
- **apl** — 只看平均亮度：`lo = 平均亮度`，`hi = 1.0`
- **white** — 只看普通白点：`lo = 白点`，`hi = 1.0`（无 HUD 剔除、无暗场兜底）
- **full** — 本补丁 L1b：bulk 白点 + 暗场 lit 判据 + 死区 + 场景融合 + 帧率归一

读法（都能在上表里逐格对上）：

- `fixed` 四个场景给出**同一组数**（0.55 / 纸白 ×1.29）——它不认识画面，满屏 UI 白照样被抬；
- `apl` 在满屏 UI 白上凑巧接近 ×1.00，但 `hud`/`mid` 把 0.50 线性抬到 ×1.33：
  平均亮度高不等于「白多」，而是「没有暗部」，抬中间调就是发灰发闷；
- `white` 在 `hud` 上被那一行 HUD 白条（1.9% 像素）钉在 0.8974 —— 0.90 线性增益只剩 **×1.002**，
  整幅画面等于没扩张；`star` 上被星点钉在 0.4893，黑底画面永远等不到扩张；
- `full` 是唯一四格都合理的：`hud` 回到 0.1897（0.90 线性 ×1.958，与无 HUD 的 `mid` 一致），
  星空 0.0200，UI 白纸白 ×1.00 不动——没有 HUD 时它必须与 `white` 逐位一致（上表 `mid` 行已对上）。

## 时间行为：切镜后多少帧到 85%

序列：32 帧中间调画面 → 32 帧 UI 白（同一条平滑链路，系数 0.10 @60 Hz）。

| 策略 | 到 85% 的帧数 | 首帧 knee_lo | 末帧 knee_lo |
|---|---|---|---|
| fixed | -1 | 0.5500 | 0.5500 |
| apl | 17 | 0.1792 | 0.6835 |
| white | 17 | 0.1826 | 0.6965 |
| full | 0 | 0.1826 | 0.7148 |

`-1` = 拐点从不动（`fixed` 本来就没有目标可追）；`0` = 切镜当帧就到稳态。
`full` 之所以能 0 帧，是因为场景判据除了平均亮度还看**白点跳变**——
同 APL 的切镜（菜单→游戏、同亮度过场）只靠平均亮度会判不出来，得爬十几帧。
