# 与 ITU-R BT.2446-1 方法 A 的定量对照

本文件由 `scripts/report_curveref.py` 生成，数字来自 `tools/hdr_curve_bt2446.c`（`--check` 会重算并逐字对比）。

## 为什么会有这份对照

`docs/SOURCES.md` §2 记的是「本案增益曲线的形状取自方法 A 的分段膝」。形状像不等于数值像：
方法 A（BT.2446-1 §4）先做**感知线性化**（`y_p = log(1+(rho_h-1)y')/log(rho_h)`，`rho(L)=1+32*(L/10000)^2.4`），再过一条分段多项式，最后**反线性化**。把它取逆拿来做 SDR→HDR，
抬的是整段中间调——因为曲线在 `y_p <= 0.7399` 段是 `1.0770*y_p`，等于给所有中低亮度乘了同一个系数。
本案只抬高光：`knee_lo` 以下恒 ×1.0000，好处是 UI、字幕、HUD 不会跟着变亮。
这条设计选择的代价，下面用 stop 量出来。

## 怎么读这两个数

- **中间调 +0.76 stop**（203 nit）：方法 A 把中低亮度整体抬 ×1.70，本案 ×1.00。如果目标是「和参考转换一模一样」，这是差得最远的一段；如果目标是「SDR 界面别变亮」，这正是我们想要的差。两个目标不可兼得，本项目选后者，并在 `docs/DESIGN.md` 写明。
- **1000 nit 时中间调差 3.0 stop**：head=10 的手机面板不存在，这条只用于说明「目标峰值越高，方法 A 抬中调越狠」——它按参考白 100 nit 放置，我们按面板实际峰值放高光，前提不同。
- **顶端 0.000 stop**（码值 255）：到纯白两侧必须重合，因为都以「SDR 白 × head」封顶；这条同时是对照表算得对的旁证——参数化错了这里就不会是 0。
- **码值 253/254 为负**（203 nit 下 −0.022/−0.012，1000 nit 下 −0.023/−0.013）：方法 A 的曲线在接近顶端时略平，本案的 smoothstep 更晚才开始收，所以这一段我们更亮。幅度小（<0.03 stop），肉眼不可见。

方法 A 里还有一项我们没有跟进：Hunt 效应色度修正（`1.8814`/`1.4746` 在 Y'Cb'Cr' 域），它作用在色差上而非亮度。本案的等价物是 CIELAB 色相保持 + 可选饱和度（`docs/COLOR.md`），但两者不是同一件事，未做等价比对，记在 `docs/SOURCES.md` §5。
