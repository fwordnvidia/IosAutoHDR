# 真实照片上的颜色保真度

网格用例（`t_hdr_color`、`t_hdr_shader_mirror`）只证明「给定 RGB 三元组，CPU 与上屏一致」；
这一页回答的是用户能看见的问题：**这张照片被推成 HDR 之后，颜色有没有偏**。

工具：`tools/hdr_color_image.c`（逐像素 sRGB → 线性 → XYZ(D65) → CIELAB）。
两张配置各跑一遍：

- `default`：`S2A_HDR_SAT=1.00`、`S2A_HDR_P3=0.00` —— **本补丁缺省**，只做亮度扩张、不动颜色；
- `tuned`：`S2A_HDR_SAT=1.15`、`S2A_HDR_P3=0.50` —— README 里给出的可选用法上限档。

| 列 | 含义 |
|---|---|
| `hue_med` / `hue_p99` / `hue_max` | 色相偏移（度），只统计输入彩度 C>1 的像素 |
| `neutral_dab` | 近中性像素（C<2）的 `a*`/`b*` 绝对位移 `Δ√(Δa²+Δb²)`；用绝对位移而不是色相角，因为 C≈1 时角度分母太小 |
| `over5_pct` | 色相偏移 >5° 的像素占比（%） |
| `gain_med_above_lo` | 只看纸白以上像素的亮度增益中位数（纸白以下按设计恒 ×1） |

## 怎么读

1. **缺省档色相偏移恒为 0.00°**——不是「很小」，是逐位不变：`sat==1 && p3<=0` 时
   `s2a_hdr_grade_rgb` 短路到 `s2a_hdr_itm_rgb`，只按 Rec.709 亮度乘一个标量。
   所以缺省档的颜色风险为零，代价是「HDR 只有亮度、没有更鲜艳」。
2. **tuned 档的中位色相偏移 <3°、最大 <3.2°**，且没有像素超过 5°（`over5_pct` 0.00）。
   参考：人眼对大面积纯色的可察觉色相阈值约 2–5°，这里全部落在「需要并排比对才看得出」的区间。
3. **近中性（白墙、灰云）的 a*/b* 位移 <0.5**（CIELAB 单位，约等于 0.5 个 JND 的一半），
   说明「灰恒为灰」在真实照片上也成立，不只是中性色网格上的性质。
4. **纸白以上的增益中位只有 ×1.00–×1.09**：三张照片的白点都接近画面最亮处，
   L1b 把纸白放在白点上，所以中调几乎不动——这正是「UI 与字幕不变亮」的直接后果。

生成：`python3 scripts/report_color_image.py`（`--check` 比对，不写文件）。
